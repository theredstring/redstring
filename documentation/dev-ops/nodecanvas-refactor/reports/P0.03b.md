## New findings
- **B-05 is now VERIFIED in effect**, not just in code, and has a user-visible reproduction:
  - Right-click a Thing and choose Save.
  - Right-click the same Thing again: the menu still offers "Save".
  - Cause: the node's `onContextMenu` closure is frozen by `<Node>`'s memo comparator, so the menu is built from the `savedNodeIds` of the node's last real render.
  - The same mechanism affects every handler passed to `<Node>`. P3.02 should turn the F12 `test.fail` into a normal `test`.
- **B-09 is VERIFIED and fixed** (see above).
- **Not a bug:** a touch pan's settled camera *is* saved. It lives in `graphViews`, not in the graph object (the F2 comment already says so). I first misread this as a save failure and confirmed the old code behaves the same way before finding the mistake. F10 now asserts on `graphViews`.
- **Behaviour to know, not a bug:** holding a node or group near the top of the screen starts edge auto-pan, so the camera never settles while the button is down. F11 pans the view first so the group label is clear of the edge. Any future flow that lifts something near an edge needs the same step.
