# P2.13 report: hover slice; `useHoverIntent`

**Status:** done (orchestrator).

## What changed
- **Vision-aid state** (`hoveredNodeForVision`, `hoveredConnectionForVision`, `activePieMenuItemForVision`) is in canvasUIStore; the fields existed since P2.01. **`layers/HoverVisionAidLayer`** subscribes and renders HoverVisionAid; NodeCanvas only writes.
- **`utils/canvas/actionHover.js`**: `setActionHover(button)` is the one stable hover report for every button (pie, header, the four control panels, gamepad focus), with the tap auto-clear timer; `getActionHoverItem()` reads it. NodeCanvas's `handlePieMenuHoverChange` is now just this function, so button hover never renders NodeCanvas. HeaderHost calls it directly, and the interim `actionHover` command is gone.
- **`hooks/useHoverIntent.js`**: the canvas dwell timer (the 180 ms enter delay, sticky edge, instant clear), moved verbatim. It writes the vision aid to the store and `hoveredEdgeInfo` to NodeCanvas, which the edge renderer still reads until P3.06.
- NodeCanvas.jsx: 15,943 → **15,789**.
