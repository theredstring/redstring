# P1.03 report: bind mousemove once

**Status:** done. Lane A worktree agent, wave 2, based on `refactor/wave2-integration` (b2314ce).

**Commit:** see `git log --grep "P1.03"` on this branch (`refactor(canvas): P1.03 bind mousemove once`).

## What changed
- Removed `onMouseMove={handleMouseMove}` from the `<svg className="canvas">`. The binding on the `.canvas-area` div stays.
- **Why the div, not the svg:** the div is the svg's ancestor, so it receives every move the svg did, plus moves over the div's other children (loading and empty states, overlays that sit outside the svg). Keeping the svg binding instead would have stopped the handler for moves over those.
- **Checked before removing:**
  - `handleMouseMove` never reads `e.currentTarget` or `e.target`.
  - It never calls `stopPropagation`. It calls `preventDefault` only on the marquee branch.
  - The svg's only mousemove handler was `handleMouseMove` itself, so nothing between the svg and the div stops propagation. Anything that reached the svg's binding also reaches the div's.
- Updated the doc comment above `handleMouseMove`. It no longer says the handler runs "over the canvas SVG".
- Removed a stale comment on the svg ("Remove pointerDown preventDefault…"), which described code that no longer exists.
- `mouseup` is untouched. The 2–3× release is P4.04.
