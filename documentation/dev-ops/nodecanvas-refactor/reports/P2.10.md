# P2.10 report: TypeList outside NodeCanvas renders (+ B-13, `useStableSelector`)

**Status:** done (orchestrator). **Commits:** `4c09950` (P2.10), `391a992` (B-13).

## What changed
- **TypeList takes no props.**
  - `nodes`, `selectedNodes` and `setSelectedNodes` were used only inside two click handlers, which now read canvasUIStore and graphStore when clicked. So `useActiveGraphNodes` (planned for P2.09/P2.10) isn't needed at all.
  - Its lists (the footer colour, the node types, the components, the connection types) come from module-level selectors through **`useStableSelector`** with equality checks. None of them depend on positions, and `graphs` is a new Map on every node move.
  - The base-"Thing" guard subscribes to one boolean instead of the whole prototypes Map. TypeList no longer subscribes to `graphs`, `nodePrototypes`, `edges` or `edgePrototypes` whole.
- **`src/components/canvas/hosts/TypeListHost.jsx`**: memo and `<Profiler id="TypeList">`. NodeCanvas renders `{!mobileLandscapeShell && <TypeListHost />}`.
- **`src/hooks/useStableSelector.js`**: `useStableSelector(useStore, selector, isEqual)`, `shallowArrayEqual`, `arrayOfRecordsEqual(keys)`. zustand's `useStoreWithEqualityFn` needs `use-sync-external-store`, which isn't installed. HeaderHost's tab selector now uses it too.
- NodeCanvas.jsx: 17,968 → **17,962**; budget lowered.

## Bug fixed
- **B-13:** clicking a type in the TypeList with nodes selected did nothing. Selection holds instance ids, but `setNodeType` takes a prototype id, so every call warned "prototype not found" (since the initial release). The selected instances are now mapped to their prototypes, deduplicated. F21 fails without the fix.

## Numbers (chambers, 3 runs, profile build)

- Total render ms fell with it: S5 103 → 59, S4 22 → 14, S7 lombardi 43 → 27, manhattan 34 → 25. Commits are unchanged.
