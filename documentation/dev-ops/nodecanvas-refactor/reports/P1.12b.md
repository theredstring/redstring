# P1.12b report: selecting a node no longer re-solves connection labels

**Status:** done (orchestrator). Implements V1 + V2 from reports/P1.12a.md, as Grant OK'd in D-18.

## What changed
- **`labelCrossingIndex`** (NodeCanvas):
  - `occluderFor` trims against the node's unselected hitbox.
  - `selectedInstanceIds` is out of the dependencies.
  - A rebuild whose polylines equal the last build's returns the previous index, with its `generation` unchanged. Otherwise a write that replaces `edges` without moving anything would re-solve every label.
- **`samePolylines(a, b)`** (new, `edgeLabelPlacement.js`) does that comparison. Unit tests are in `labelCrossings.test.js`.
- `labelObstacleOptions` keeps its selection dependency. Obstacle identity isn't part of a label's signature, so it never re-solved anything (P1.12a, V3).
- NodeCanvas.jsx stays at 18,412 lines: the memo's comments were condensed to make room.

## Effect
- **Label fixture (jsdom):**
  - Selecting the hub or the leaf re-solves only labels whose own drawn route changed. The snapshot test now asserts this.
  - Every "labels that moved" list for the routed styles is `[]`. Before, clean moved 7 labels and 5 labels, manhattan 2 and 2, lombardi 1.
  - Every "at rest" snapshot is unchanged.
  - Straight routing is unchanged (not a routed style; its labels sit on the drawn line).
- **S7 on chambers** (profile build; before: the 5-run baseline at c34b0ca; after: 3 runs):

| Scenario | Commits | Total ms |
|---|---|---|
| S7-lombardi | 20 → 20 | 67.9 → 63.6 |
| S7-manhattan | 20 → 20 | 54 → 46.1 |

  The saving is label work inside each render, not renders. Chambers' largest graph has 40 connections, so it's modest there; it grows with the number of named connections.

## Verification

- NodeCanvas tests and `test/meta`: 56 passed.
- `lint:undef` passes.
- Playwright: 34 passed.
