# P1.05 report: panel resize without a commit every frame

**Status:** done (orchestrator).

## What reads the width during a drag
A grep of `leftPanelWidth`/`rightPanelWidth` in NodeCanvas found three readers:
- the overlay resizer bars' position (`renderPanelResizers`)
- `beginDrag`'s start width
- `getFramingRegion`, which is only used when the camera frames something

The panel itself follows the `panelWidthChanging` window event, not NodeCanvas state. So nothing needed to move out of NodeCanvas first, and this wasn't deferred to P2.12.

## What changed
- **`applyResizeUpdate`:** writes the width to `leftWidthRef`/`rightWidthRef` and moves the bar with a direct `style.left/right` write through new element refs. It still dispatches `panelWidthChanging`, and no longer sets state.
- **`endDrag`:** commits the width once, then persists and broadcasts it as before. The duplicated left/right blocks are now one loop.
- **`beginDrag`:** reads the start width from the refs.
- **`resizerOffset(width)`** (module level): the bar's offset, shared by the render and the drag.
- The gamepad resize path goes through the same `applyResizeUpdate`/`endDrag`, so it gets the same treatment.
- NodeCanvas.jsx: 18,412 lines, unchanged.

## Effect
**S9** (drag the right resizer 300 px in 60 moves; chambers, profile build, 3 runs, against the c34b0ca baseline):

| | Before | After |
|---|---|---|
| Commits | 71 | 17 |
| NodeCanvas runs (rendered) | 65 (64) | 7 (6) |
| Total ms | 187 | 40 |

## Verification
- F8 (both panels widen and narrow, width persisted) passes. Playwright: 35 passed.
- NodeCanvas tests: 56 passed. `lint:undef` passes.
- If NodeCanvas re-renders for another reason mid-drag, React doesn't overwrite the bar: the rendered `left`/`right` value hasn't changed since the last render, so React doesn't write it.
