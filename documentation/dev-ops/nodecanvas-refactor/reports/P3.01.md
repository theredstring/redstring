# P3.01 report: writes elsewhere in the universe don't render the canvas

**Status:** done (orchestrator).

## What changed
- **`graphsMap` is a live view** (`src/utils/liveMapView.js`): `get`/`has`/`size`/iteration read `useGraphStore.getState().graphs` on every call.
  - Callbacks and hooks (`useGraphLayout`, `useCanvasKeyboard`, `handleDragEnd`, the definition and group handlers) always see current graphs.
  - Its identity, which memos and effects key on, changes only when the active web's object changes. While a node previews its definition, it changes on any graph change, because that preview's description is read during render.
  - Every other `graphsMap` read was checked: they are callback-time or active-web reads. Node subscribes to definition graphs itself while previewing.
- **Image cache:** `imageCacheMap`, `loadingImagesMap` and `failedImagesMap` are narrowed to prototypes on the active web by **`usePickedEntries`** (new, in `hooks/useStableSelector.js`), which keeps their identity while those entries are unchanged.
- **Not narrowed:** `nodePrototypesMap`, `edgesMap` and `edgePrototypesMap`. No scenario in the card needs them, and narrowing prototypes safely means defining everything the canvas displays (the carousel's abstraction chains, types, connection definitions). Candidate for a later card with the same live-view pattern.
- NodeCanvas.jsx: 15,718 → **15,732** (+14: the view keying and the pick).
