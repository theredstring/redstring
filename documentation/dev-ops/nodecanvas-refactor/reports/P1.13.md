## B-07: `onNavigateDefinition` updaters: fixed
- **Re-verified.** There were three inline `onNavigateDefinition` handlers: the main node render, the dragged-node render, and the active-node render. All three called `setNodeDefinitionIndices(prev => new Map(prev.set(contextKey, newIndex)))`. `nodeDefinitionIndices` is local `useState`, so each call mutated the committed Map inside the updater before copying it.
- **Fix.** All three now use `prev => { const next = new Map(prev); next.set(contextKey, newIndex); return next; }`. The resulting state is identical, and the previous Map is never touched.
- **Verification:**
  - `grep 'new Map(prev.set('` now returns nothing.
  - The other two `setNodeDefinitionIndices` updaters (the carousel decomposition index at about line 9462, and the pie `setIndex` at about line 9644) already use `new Map(prev).set(…)`, which copies first, so they were pure already.
  - Tests: smoke 7/7, render-budget 3/3, everything under `test/hooks` (214 tests) passes.
  - `npm run build`: `✓ built in 8.15s`.
  - jsdom doesn't exercise definition navigation (it needs a node with several definition graphs and the Node arrows), so the fix was verified by reading the code, not by an automated test.

## B-03: `openOnboardingModal` listener: needs Grant's decision
**Re-verified.** The NodeCanvas effect "Open Onboarding modal when event is dispatched from Help menu" calls `setShowOnboardingModal(true)` inside a `try {} catch {}`. `setShowOnboardingModal` isn't defined anywhere; with the project lint config it is the only `no-undef` in NodeCanvas. The ReferenceError is swallowed, so the event does nothing.

**Dispatchers.** Both are user-visible, and both currently do nothing:
- `src/RedstringMenu.jsx` (~937): Help submenu → **"Show Welcome Screen"**.
- `electron/main.cjs` (~518) app menu → **"Show Welcome Screen"** → `sendMenuCommand('welcome')`. That command is received by `src/hooks/useCanvasKeyboard.js` (~247, `case 'welcome'`), which re-dispatches `openOnboardingModal`.

**History** (`git log -S'setShowOnboardingModal'`):
- `showOnboardingModal` drove `AlphaOnboardingModal`, a welcome screen whose "continue" step handed off to `StorageSetupModal`.
- **5d6e650** (2026-01-16, "Remove AlphaOnboardingModal and integrate initial setup into a redesigned StorageSetupModal") deleted that modal and its state but left this listener behind. Both "Show Welcome Screen" items have been no-ops since then.
- 6af9556 and 9fd9e77 later added more `setShowOnboardingModal(false)` calls, which were just as undefined. 3afbefe (2026-09-23) removed them.

**Why I didn't fix it.** The modal it opened no longer exists. But its role was folded into `StorageSetupModal`, so what the menu items *should* do now is a product call:
- `StorageSetupModal` is not a passive welcome screen. It is the universe-setup wizard: the "Welcome to Redstring" heading over "Set up your first Universe", universe naming, and Git/local "slots". It opens automatically on a fresh start and on onboarding resume. Re-pointing the menu item at it would drop a user who already has a universe loaded into new-universe setup, next to the Git first-contact code.
- Removing the dispatchers means removing two visible menu items, in files outside this lane. One of them, `useCanvasKeyboard.js`, is being edited by Lane C (P1.11) right now.

**Options for Grant:**
- **A. Re-point:** the listener calls `setShowStorageSetupModal(true)`. This is a one-line NodeCanvas change and the menu items stay. First, someone needs to check what `StorageSetupModal` does when opened over a loaded universe.
- **B. Remove:** delete the listener (NodeCanvas), the RedstringMenu item, the Electron menu item and the `'welcome'` case in `useCanvasKeyboard`. Do the last one after P1.11 merges.
- **C. Build a real welcome screen:** a new feature, which would go in the new structure rather than NodeCanvas. Then re-point to it.

My read: "Show Welcome Screen" in a Help menu promises a passive intro, which `StorageSetupModal` isn't. So **B** is the honest minimal fix unless Grant wants **C**. A needs a safety check first.
