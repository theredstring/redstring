# P5.04a report: carousel frames skip NodeCanvas (F-06)

**Status:** done (orchestrator). This is the per-frame part of P5.04. The rest of P5.04 (moving the carousel physics and `AbstractionControlPanel` into a host) is still open and follows P5.02a. Branch `refactor/carousel-sweep`, commit e6f3f37.

## Why
F-06: the carousel reports its focused node's scale, size and identity on every physics frame. All three were NodeCanvas state. The size fed the pie-data effect, which wrote a new `currentPieMenuData`, which NodeCanvas also subscribed to. So every frame cost **two** NodeCanvas renders: S12 ran NodeCanvas 148 times.

## What changed
- **Scale and size are refs.**
  - `setCarouselFocusedNodeDimensions` stores the size and calls `rebuildPieMenuDataRef.current()`. That is the pie-data effect's body, unchanged except that it reads the size from the ref. It is assigned every render, and the same effect still runs it on the same dependencies.
  - The scale is read "as of the last render" (`carouselFocusedNodeScaleRef.current` captured in render), as the state was. Only the open-time framing reads it.
- **`NodePieMenuLayer`** (`components/canvas/layers/`) reads `currentPieMenuData` from canvasUIStore and renders the node PieMenu. NodeCanvas passes every other prop as before, and subscribes only to the target id (`currentPieMenuNodeId`, used for stacking and `isVisible`) and whether data exists (`hasPieMenuData`).
- **`carouselFocusedNode` uses `useTrackedState`.** It changes only when the focus moves to another level.
- The pie effect's empty `else if` branch (comments only) and three orphan `//` lines are gone.

## Behaviour
- **One intended difference:** the pie now tracks the focused node's size in the **same frame** the carousel reports it. Before, it caught up a render later. Grant should see bubbles hugging a growing/shrinking node at least as tightly as before.
- Every reset site (graph change, carousel teardown, back-to-civilization) also changes a dependency of the pie effect, so the effect still rebuilds from fresh values after them.
