# P2.12 report: `PanelResizers`; one source for panel width (+ B-15)

**Status:** done (orchestrator). **Commits:** `816af1b` (shell-shot seeding), `6d46a49` (P2.12).

## What changed
- **`src/components/canvas/PanelResizers.jsx`** (memo) is rendered by NodeCanvas where `renderPanelResizers()` was. It holds, moved as they were:
  - the drag refs, hover and fade state, `beginDrag` / `applyResizeUpdate` / `endDrag`, and the window listeners (including touchcancel/pointercancel)
  - the gamepad handle, now filled into the `controlRef` prop together with `isDragging()`. NodeCanvas's canvas-press guard uses that instead of the drag refs.
- **Committed widths** are `canvasUIStore.leftPanelWidth` / `rightPanelWidth`, read from the persisted value and clamped. PanelResizers keeps them in step with `panelWidthChanged` and window resizes.
  - **`useViewportBounds`** (8 consumers, each of which kept its own copy and its own listener) reads them from the store.
  - **`getFramingRegion`** reads them when it runs.
  - Panel's own `panelWidth` state is unchanged; it still follows `panelWidthChanging` and `panelWidthChanged`.
- **`src/utils/canvas/panelWidth.js`** holds the width constants, `clampOverlayPanelWidth`, `readPersistedPanelWidth` and `resizerOffset`.
- **B-15 (fixed):** `useViewportBounds` fell back to 280 px while the panels open at 250. On a fresh profile, everything placed off the viewport bounds (the save pill, the edge glows, modals) sat 30 px off.
- NodeCanvas.jsx: 16,320 → **15,943**.
