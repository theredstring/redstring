# P2.08 report: Header wired by `HeaderHost`; canvas command registry (+ P2.06e, B-12)

**Status:** done (orchestrator). **Commits:** `90c0b57` (perf harness), `0d54da5` (P2.08), `90120ef` (B-12).

## What changed
- **`src/utils/canvas/canvasCommands.js`** (D-20): `registerCanvasCommands`, `runCanvasCommand`, and `useCanvasCommands(handlers)`, which registers once on mount and forwards to the latest handlers.
  - NodeCanvas registers `autoLayout`, `snapToGrid`, `condense`, and `actionHover` (the header's hover chip; interim until P2.13).
  - Not registered yet, because nothing calls them: `navigateTo`, `focusNode`, `startHurtleFromPanel`. P2.09 adds what the Panels need. Force sim opens through its store flag.
- **`src/components/canvas/hosts/HeaderHost.jsx`**: renders `<Header>` inside `<Profiler id="Header">`, wired to graphStore, canvasUIStore, the command registry and a file-actions module. Its one prop is `hidden` (the landscape shell), so a NodeCanvas render never re-renders it.
  - `headerGraphs` is selected with an equality check on the tab fields. `graphs` is a new Map on every node move, so a plain selector would re-render the header on every drag frame.
  - The bookmark state is a boolean selector. The exclusive-panel flag and fullscreen come from `useSyncExternalStore` on `resize` / `fullscreenchange`.
- **Moved to canvasUIStore:** `trackpadZoomEnabled` (NodeCanvas binds it; Header toggles it) and the gamepad's `headerFocusedGraphId` (`useGamepad` writes the store and no longer returns it).
- **P2.06e done here:** `src/services/universeFileActions.js` holds new / open / save / open-recent / export. They were about 170 lines inline in the Header JSX and needed nothing from the canvas. Unused `getFileStatus()` debug reads were dropped.
- **Deleted from NodeCanvas:**
  - the `headerGraphs` memo and fullscreen state
  - `bookmarkActive`, `handleToggleBookmark`, `handleProjectTitleChange`, `runActiveExport`
  - a `headerGraphs` "validation" effect that could never fire (the memo already dropped every graph it tested for)
  - an effect with an empty body whose only effect was subscribing NodeCanvas to `openGraphIds`, so closing or reordering a tab no longer renders the canvas
- NodeCanvas.jsx: 18,362 → **17,994**; budget lowered.

## Deviations from the card
- **HeaderHost renders in NodeCanvas's header slot, not from App.** Moving the element into App changes the shell's flex composition; that is P2.11's job, with its pixel-identical acceptance. With one boolean prop it is already independent of NodeCanvas renders; P2.11 moves the element.
- **The orphan-graph cleanup effect stays in NodeCanvas.** It runs whenever `nodePrototypes` changes, which is data hygiene, not header work. NodeCanvas already subscribes to that. In HeaderHost it would subscribe the header to every prototype edit.

## Bug fixed
- **B-12:** View → Snap to Grid and View → Grid → Lattice / Dot did nothing. RedstringMenu takes `onSnapToGrid`, `gridAppearance` and `onSetGridAppearance`, but Header never accepted or forwarded them (since 1eca3a8), so Lattice always showed the checkmark. NodeCanvas even passed `onSnapToGrid` and the appearance props to Header, which dropped them. F19c fails without the fix.
