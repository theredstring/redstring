## What changed

### 1. `useCanvasTouch` params (X-04, plus `isPaused`)
- Removed from the hook signature, the NodeCanvas call site, and the hand-built param objects in all three touch tests (`test/hooks/useCanvasTouch.{panCatch,pinchCalibration,pinchOnNode}.test.jsx`):
  - `panOffset`, `zoomLevel`, `setPanOffset`, `setZoomLevel`: never read by the hook
  - `recentlyPanned`, `setLastInteractionType`: dead state
  - `isPaused`: not listed in X-04, but it is the same always-false X-01 state
- Simplified the hook's five guards as if `isPaused` and `recentlyPanned` were the constant `false`. Removed the `setLastInteractionType('plus_sign_shown_touch')` write.
- No other caller exists. `AbstractionCarousel.jsx` only mentions the hook in comments.

### 2. Dead state (X-01)
- Deleted `hasMouseMovedSinceDown`, `middleZoomAnchor`, `lastInteractionType`, `nodeSelectionGrid`, `recentlyPanned`, `isPaused` and `autoLayoutRunning`, with every setter call.
- `isPaused` and `recentlyPanned` guards were simplified as the constant `false`:
  - `handleNodeMouseDown` (2 guards)
  - `handleMouseMove`
  - `handleMouseDown` (2 guards)
  - `handleMouseUp`
  - `handleCanvasClick` (3 guards; the `'blocked_click'` write went with them)
  - the node-group inner-canvas `onClick`
- `isPausedRef` was deleted too, and NodeCanvas no longer passes `isPaused` to `useCanvasKeyboard` or `isPausedRef` to `useGamepad`. Both hooks read them only as falsy guards (`isPaused || …` and `!p.isPausedRef?.current`), so passing `undefined` behaves identically. I didn't edit those hooks because they aren't in this lane (see Handoff).
- `autoLayoutRunning` was never set to true, so `ForceSimulationModal` now gets `isOpen={forceSimModalVisible}`. The `autoStart` and `invisible` props were dropped; they were always `false`, which is the component's default. The two `setAutoLayoutRunning(false)` calls are gone.
- `handlePlusSignClick` no longer computes a node-selection-grid position that nothing rendered.

  - `pinchSmoothingRef` is now `useRef({ lastFrameTime: 0 })`, the only field `useCanvasTouch` reads. It is still passed to `useCanvasTouch` and `useNodeDrag`.
  - `renderConnectionNamePrompt` and `renderCustomPrompt` (both "Deprecated – replaced by UnifiedSelector").
  - The helpers only those two used: `handleDialogColorPickerOpen`, `handlePromptSubmit`, `handleNodeSelectionGridClose` and `dialogContainerRef` (see NEW-4).
  - Also `isNearEdge`, `handleEdgeClick`, `handleEdgeMouseEnter`/`Leave`, `schedulePositionUpdate`/`flushPositionUpdates` (with their `pendingPositionUpdates`/`positionUpdateScheduled` refs) and `nodesVisibleInStrictViewport`.
- **X-03:** the `useNodeActions` and `NodeSelectionGrid` imports.
- **X-06:**
  - refs: `lastHoverCheckRef` (plus its orphaned `HOVER_CHECK_INTERVAL_MS`), `isKeyboardZooming`, `resizeTimeoutRef`, and `prevZoomForWatchdog` with its sync effect
  - module constants: `MOUSE_WHEEL_ZOOM_SENSITIVITY`, `TOUCH_PINCH_SENSITIVITY` and `TOUCH_PINCH_MAX_RATIO_STEP`

## New findings
- **NEW-4: X-02 slightly misdescribed `dialogContainerRef`.** It was also passed to the dialog `ColorPicker` as `parentContainerRef`. That was inert: `ColorPicker` declares `parentContainerRef = null` and never reads it, and the only element carrying the ref lived in the never-rendered `renderCustomPrompt`, so `.current` was always null. I removed the prop along with the ref. `ColorPicker`'s `parentContainerRef` prop is itself dead: its other two callers pass `null`.
- **NEW-5: About 99 more `no-unused-vars` remain in NodeCanvas** under the project lint. These are candidates for a follow-up sweep; each needs the same setter and hooks re-check before deletion. The same lint reports 52 `exhaustive-deps` warnings, relevant to P1.10 and P3.
- **NEW-6: some dead parameters live in hooks outside this lane:**
  - `useCanvasKeyboard` still declares `isPaused`, now always `undefined`.
  - `useGamepad` still declares `isPausedRef`, now always `undefined`.
  - `useNodeDrag` still cancels `pinchSmoothingRef.current.animationId` in two places (≈2045, ≈2127), which can no longer be set.
  - All three are behaviour-neutral as they stand.
