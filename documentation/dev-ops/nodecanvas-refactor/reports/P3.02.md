# P3.02 report: node handlers read the latest render (B-05)

**Status:** done (orchestrator).

## What changed
- **`src/hooks/useLatestRef.js`**: a ref whose `current` is the latest committed value, updated in a layout effect.
- **NodeCanvas `nodeScope`** holds the latest `handleNodeMouseDown`, `touch`, `getContextMenuOptions`, `handleCommitCanvasEdit`, `startHurtleAnimation`, `activeGraphId` and `handleNodeConvertToNodeGroup`. Every Node handler reads them through it, so a Node that hasn't re-rendered (its memo ignores functions) never runs a stale render's closure.
- **B-05 fixed:**
  - the context menu offered "Save" after a save
  - `handleNodeMouseDown` read stale pause, panel and zoom settings, for example collapsing the right panel and then double-clicking a node that hadn't re-rendered
  - `touch.handleNode*` had the same problem
- **`nodeCallbacks`**: the definition callbacks (create, add, delete, expand, navigate, convert, cancel-edit), copied into all three Node blocks, are defined once and spread in. The two later copies differed only in comments and an empty `else`.
- NodeCanvas.jsx: 15,789 → **15,718**.

## Deviation from the card
- Handler **identities** are not stable per render: they're fresh arrows that read the latest scope. Node's comparator ignores functions by design, so identity doesn't affect it, and correctness is what B-05 needed. Stable identities come with P3.08, when Node gets one prop block and an id-taking API.
- **Edge handlers and group-title handlers** needed no change: edges and group titles are rebuilt on every NodeCanvas render (plain functions, not memoized children), so they can't hold stale closures. That changes with P3.04 and P3.06, which should use the same ref pattern.
