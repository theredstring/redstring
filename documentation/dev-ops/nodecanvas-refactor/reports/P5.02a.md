## 0. The shape in one paragraph

The node pie menu has **no explicit state**. Its lifecycle is the combination of a *target*
(`selectedNodeIdForPieMenu`), a *copy of what it draws* (`currentPieMenuData` + `isPieMenuRendered`), a
*"something is animating out on purpose"* flag (`isTransitioningPieMenu`) and three *"what to do when the
shrink ends"* slots (`pendingAbstractionNodeId`, `pendingDecomposeNodeId`, `isCarouselStageTransition`).
`PieMenu` owns the real animation state (`null → popping → visible_steady → shrinking → null`) and reports only
one event upward: the end of a shrink (`onExitAnimationComplete`). Every transition therefore works as
**"set a pending slot + `isTransitioningPieMenu = true` → PieMenu shrinks → the inline exit callback reads the
slots and decides the next state → the `isTransitioningPieMenu` change re-runs the pie-data effect, which
re-mounts the menu, which pops."** The carousel adds a second, 200 ms timer-driven machine inside
`AbstractionCarousel` (`entering → visible`, `exiting → onExitAnimationComplete`) and three "don't clean me up
yet" latches (`justCompletedCarouselExit`, `carouselExitInProgressRef`, `isPieMenuActionInProgress`). A
"graph-change cleanup" effect that actually fires on four different dependencies resets ~30 fields unless one
of five guards holds.

## 4. The current machine, written out

### 4.1 Pie target: the "reconcile" rule (E-sel)

E-sel is a pure function of its eight deps, re-run whenever one changes:

```
reconcile():
  if selectionStart != null: return                           // marquee still dragging
  if selectedInstanceIds.size == 1:
      if !isTransitioningPieMenu: target = the one id           // else wait; re-runs when the flag falls
      return
  // 0 or ≥2 selected
  if abstractionPrompt.visible && abstractionCarouselVisible: return
  if carouselAnimationState == 'exiting':                    return
  if justCompletedCarouselExit:                               return
  if abstractionCarouselVisible && target: carouselAnimationState = 'exiting'; return   // no pie shrink first
  target = null
```

Because `isTransitioningPieMenu` is a dep, **a click on another node while a transition plays is applied when
the transition ends** (not by H-pieExit, despite its comment). That is load-bearing.

### 4.2 Pie lifecycle states (derived)

| Derived state | Condition | PieMenu |
|---|---|---|
| **closed** | `!isPieMenuRendered \|\| !currentPieMenuData` | not mounted |
| **open** | mounted ∧ `isVisible` | popping → visible_steady |
| **closing** | mounted ∧ `!isVisible` | shrinking → H-pieExit |
| **hidden-open** | orbit or dragging-this-node: `isVisible` false, target kept | shrinks, H-pieExit clean branch; returns when the condition clears (E-rebuild dep) |

`isVisible` (~10606–10616):
```
currentPieMenuNodeId === selectedNodeIdForPieMenu
&& !semanticOrbitActive
&& (!isTransitioningPieMenu || abstractionPrompt.visible || carouselAnimationState === 'exiting')
&& !(draggingNodeInfo targets selectedNodeIdForPieMenu)
```
So closing is started by any of: target changes (≠ drawn node) or null; transitioning rises; orbit; drag.

**H-pieExit decision table** (runs when the shrink ends; reads the render-scope values of the last render):
always first: `isPieMenuRendered=false`, `currentPieMenuData=null`, `pendingAbstractionNodeId=null`,
`pendingDecomposeNodeId=null`; `lastActiveNodeId := selectedNodeIdForPieMenu`.

| # | Condition (first match) | Writes | Meaning |
|---|---|---|---|
| 1 | transitioning ∧ pendingAbstraction | transitioning=false; if node found: `abstractionCarouselNode=node`, anim=`entering`, carousel visible, target=pendingAbstraction | pie → carousel |
| 2 | transitioning ∧ pendingDecompose | transitioning=false; if node found: preview = (preview==id ? null : id), target=id | pie → decompose (toggle) |
| 3a | transitioning ∧ carousel visible ∧ stage flag | flag=false, transitioning=false, stage 1↔2, target=lastActive if set | carousel stage swap |
| 3b | transitioning ∧ carousel visible ∧ ¬flag | anim=`exiting` (**transitioning stays true** until H-cxDone) | carousel exit, phase 1 |
| 4 | transitioning | transitioning=false; (click-away ref: dead); `sel := first selected id`: if sel → preview toggled **for sel**, target=sel; else preview=null | Compose (and any other generic transition) |
| 5 | else | transitioning=false (no-op) | plain dismiss / orbit / drag / retarget-away |

After H-pieExit, the next commit re-runs E-rebuild (because `isTransitioningPieMenu` and/or target/preview/stage
changed): if a target remains and nothing blocks, data is rebuilt and `isPieMenuRendered=true` → a **fresh
PieMenu mounts and pops**. That is the "shrink, then pop the next menu" sequencing of every pie transition.

### 4.3 Transitions and their cascades

Notation: `→` next commit; `⟶` time-based (animation or timer).

**T1 Open by selecting a node** (mouse click, touch tap after `NODE_DOUBLE_TAP_MS`, marquee landing on one node, Wizard select).
`selectedInstanceIds={A}` → E-node (show node panel) and E-sel (target=A) → E-focus (`focusNodeInView`),
E-page (0), E-rebuild (data, rendered) → layer mounts, PieMenu `popping` ⟶ `visible_steady`.
(Touch's deferred tap and the Wizard also write target directly; E-sel then writes the same value.)

**T2 Retarget A→B while open** (click another node). E-sel target=B → one commit where `currentPieMenuNodeId`
(A) ≠ target (B): `isVisible=false`, PieMenu's effect sets `shrinking`; in the same flush E-rebuild writes B's
data → next render `isVisible=true` with `shrinking` → PieMenu sets `popping`. Net: B pops; no H-pieExit, no
unmount. The transient `is-shrinking` render is sync-lane and probably never painted (ambiguity A-2).

**T3 Dismiss** (click bare canvas / touch tap-off / Delete / drag start). Selection empty → E-sel target=null
(or the carousel guards apply) → `isVisible=false` ⟶ shrink ⟶ H-pieExit row 5 → `closed`; E-vision clears the
hover chip; E-node animates the node panel out ⟶ its `onAnimationComplete` → `shouldShow=false`.

**T4 Pie → decompose** (`decompose-preview` action, nodePieButtons ~85; context-menu Decompose calls the same
action 100 ms after selecting). `pendingDecomposeNodeId=A`, transitioning=true → E-watchdog arms (1200 ms) →
`isVisible=false` ⟶ shrink ⟶ H-pieExit row 2: preview=A, transitioning=false → E-decomposeFrame frames the
expanded node; E-rebuild builds the decompose set with expanded dims → pop; E-node switches the panel to
`decompose` mode; E-cleanup re-runs (transitioning dep) and is blocked by the `size==1 ∧ target` guard.
Blocked if `!carouselVisible ∧ anim=='exiting'`.

**T5 Compose from the pie** (`compose-preview`, ~811). transitioning=true (no pending slot) ⟶ shrink ⟶
H-pieExit row 4: preview toggled for the **currently selected** node (normally A → null), target=A →
E-recompose frames A; E-rebuild builds the default set → pop.
**T5b Compose from the control panel** (`onCompose`, ~11327) sets `previewingNodeId=null` directly: no shrink;
E-rebuild swaps the buttons under a visible menu (new ids pop individually via `enteringIds`). **T5c** panel
Decompose (`handleNodePanelDecompose`) is the same in reverse. (A-7.)
**T5d Decompose Further** (`decomp-further(-empty)`): graphStore creates a group; preview=null,
transitioning=false, `selectedGroup=group`, selection empty, group panel `shouldShow=true`, node panel cut.
Selection empty → E-sel target=null → pie closes (T3); E-group shows the group panel.

**T6 Pie → carousel** (`abstraction`, ~101). `pendingAbstractionNodeId=A`, transitioning=true ⟶ shrink ⟶
H-pieExit row 1: carousel node, `entering`, visible, target=A → same commit's effects: E-cxFrame
(`runFramingAfterCommit` → `animateCanvasView` 320 ms); E-abs shows the abstraction panel and **cuts** the node
panel (no exit animation); E-rebuild builds the carousel stage-N set (N = whatever `carouselPieMenuStage` holds —
see NEW-4) centred on the carousel → pop; E-cleanup re-runs and is blocked (carousel visible). Carousel mounts;
its report effect calls `setCarouselFocusedNodeDimensions` → `rebuildPieMenuDataRef` (per frame thereafter, P5.04a)
⟶ 200 ms → H-cxState `visible`.
**T6b Direct open** (context-menu "Generalize / Specify", `handleNodePanelAbstraction`): carousel node,
`entering`, visible, target=A, selection={A} in one batch; no shrink — an open default pie swaps to the carousel
set in place; a closed pie pops.

**T7 Stage change** (`carousel-plus` 1→2, `carousel-back-stage2` 2→1). stage flag=true, transitioning=true ⟶
shrink ⟶ H-pieExit 3a: stage toggled, flag false, transitioning false, target kept → E-rebuild → pop the other
stage. These buttons stay clickable during the shrink.

**T8 Abstraction prompt.** `carousel-add-above/below` (stage 2) → `abstractionPrompt={visible, direction,
nodeId: prototypeId of the focused node, carouselLevel}`; the pie stays open (no transition).
- **Submit** (`submitAbstraction` tail): graphStore chain add; prompt hidden; carousel visible (no-op);
  `carouselFocusPrototypeRequest=newId`; stage=1; flag=false; target=carousel node → E-rebuild swaps stage-2
  buttons for stage-1 buttons **in place** (no shrink; new ids pop). Carousel jumps focus to the new level.
- **Cancel** (`onClose`, ~11280): prompt hidden; stage=1; **flag=true** (NEW-2); target=carousel node if none.
- E-promptStage enforces "prompt visible ⇒ stage 2" (defensive).

**T9 Carousel close with the pie returning** — stage-1 `carousel-back` (~376), or H-cxClose from Escape,
mouse click-away, `AbstractionControlPanel.onDismiss`, touch H-cxReq with a target.
`justCompletedCarouselExit=true`, click guard (100 ms), transitioning=true [H-cxClose also: flag=false] ⟶ pie
shrink ⟶ H-pieExit 3b: anim=`exiting` (transitioning stays true) ⟶ carousel 200 ms (non-current levels fade) ⟶
H-cxDone (§4.5): carousel hidden, `hidden`, transitioning=false, selection={A}, target=A,
`pendingCarouselReturnFocusRef=A`, 300 ms timer → next commit: carousel unmounts; E-abs animates the abstraction
panel out; E-node shows the node panel; E-return frames A; E-rebuild builds the default set at A's real position →
pop; E-cleanup re-runs twice (now and at +300 ms) and is blocked by guards each time.
During the whole exit, canvas clicks do nothing (click guard, then `exiting`, then exit guards in H-click).
Total ≈ 100–220 ms shrink + 200 ms, inside the 1200 ms watchdog.

**T10 Carousel leave with the target cleared first** — `carousel-swap` (+ `pendingSwapOperation`),
`carousel-expand` (+ `startHurtleAnimation`, 400 ms flight; the no-definition path first waits 50 ms),
`carousel-ask-wizard` (+ `rs-ask-wizard-abstraction` event). All: click guard 100 ms, target=null,
transitioning=true (**`justCompletedCarouselExit` is not set**) ⟶ shrink (target null ⇒ `isVisible` false) ⟶
H-pieExit 3b (`lastActiveNodeId` is null, irrelevant) ⟶ 200 ms ⟶ H-cxDone: swap applied if pending, then the
same restore as T9 (selection + target + return focus to the carousel's original instance).

**T11 Touch close with no pie** (H-cxReq, no target) and **T12 defensive teardown** (H-click / H-groupClick,
carousel visible ∧ no target): visible=false, node=null, `hidden`, stage 1, focused node/dims null, **no exit
animation**. Next commit E-cleanup runs (carousel-visible dep) and, since there is no single-selection+target,
performs the **full reset** (§4.9) — including an instant cut of the abstraction panel (E-abs then only sets
`visible=false` on an already-unmounting panel). (A-8.)

**T13 Selection lost while the carousel is up** (any writer that empties the selection without going through
H-click, e.g. Cmd+X, touch paths, Wizard). E-sel sets anim=`exiting` without shrinking the pie ⟶ 200 ms ⟶
H-cxDone restores selection={carousel node} and target. The pie stays up in carousel mode during the fade, then
E-rebuild swaps it to the default set in place. (A-4, NEW-7.)

**T14 Orbit.** Pie `orbit` action: `semanticOrbitActive=true`, node panel visible=false, **target kept** →
`isVisible=false` ⟶ shrink ⟶ H-pieExit row 5 (closed, page kept because the target didn't change). Exit orbit
(`exitOrbitMode`) → E-rebuild (orbit dep) → pop on the same page; node panel re-shown. Context-menu and panel orbit
clear the target instead (page resets to 0 via E-page).

**T15 Drag the pie's node.** `draggingNodeInfo` matches target → `isVisible=false`, E-rebuild frozen ⟶ shrink ⟶
row 5 → closed. Drop → `draggingNodeInfo` null → E-rebuild → pop at the new position. Touch long-press drag
clears the target instead (T3).

**T16 Watchdog.** Transitioning true for 1200 ms (no shrink could happen: e.g. H-cxClose with nothing rendered)
→ transitioning=false, flag=false → E-sel re-runs (may set target), E-rebuild may reopen, E-cleanup re-runs
(may full-reset if no single selection+target).

**T17 Graph change** — §4.9.

### 4.4 The exit latches, precisely

| Latch | Raised | Lowered | Guards |
|---|---|---|---|
| `isPieMenuActionInProgress` | H-cxClose; `carousel-back/swap/delete/expand/ask-wizard` | own `setTimeout(100)` (never cancelled) | H-click returns early |
| `justCompletedCarouselExit` | `carousel-back`, H-cxClose — *before* the exit | H-cxDone's `setTimeout(300)` (never cancelled) | E-sel (don't clear target), E-cleanup, H-click / H-groupClick (don't clear selection) |
| `carouselExitInProgressRef` | H-cxDone — *after* the exit | same 300 ms timer | E-cleanup, H-click, H-groupClick |

So the exit window is: Back/close → [click guard 100 ms] … [exit guard: from the click to exit+300 ms]; for
T10/T13 only the ref covers exit…exit+300 ms. Note `setJustCompletedCarouselExit(false)` when it is already false
changes nothing, so on T10/T13 E-cleanup is **not** re-run at +300 ms (matters for NEW-3).

### 4.5 `onCarouselExitAnimationComplete` (H-cxDone, 4750–4839)
Deps `[abstractionCarouselNode?.id, pendingSwapOperation, activeGraphId, storeActions]`.
1. `nodeIdToShowPieMenu = abstractionCarouselNode?.id`.
2. If `pendingSwapOperation`: compute centre-preserving position from old/new dims; `storeActions.updateNodeInstance(activeGraphId, originalNodeId, {prototypeId, x, y}, {finalize:true})`; set carousel node to a swapped copy (overwritten by step 4 in the same batch); `pendingSwapOperation=null`.
3. `carouselExitInProgressRef=true`.
4. carousel visible=false, node=null, anim=`hidden`, transitioning=false.
5. (click-away ref is always false) if node id: selection={id}, target=id, `pendingCarouselReturnFocusRef=id`.
6. `setTimeout(300)`: `justCompletedCarouselExit=false`, ref=false.
Not reset here: `carouselPieMenuStage`, `isCarouselStageTransition`, `carouselFocusedNode`, focused dims/scale refs.

### 4.7 Control-panel latches

Pattern for each panel P: **SHOW** → `P.shouldShow=true, P.visible=true`; **HIDE** → `P.visible=false`
(animated; unmount on its exit callback); **CUT** → both false (instant, no exit animation).
Exclusivity as written today (asymmetric, keep as-is):

| Showing | node | connection | group | abstraction |
|---|---|---|---|---|
| node (E-node) | — | CUT | HIDE + `selectedGroup=null` | CUT |
| connection (E-conn) | CUT | — | HIDE + `selectedGroup=null` | CUT |
| group (E-group) | CUT | CUT | — | CUT |
| abstraction (E-abs) | CUT | — | — | — |

Each "want" is a pure function of selection/edge/group/carousel/prompt/orbit/marquee/settings (table §2). When
want is false and the panel is visible → HIDE. Extra writers: E-closeAll (HIDE all four), E-cleanup (CUT
abstraction), `exitOrbitMode` (SHOW node), orbit actions (node `visible=false` only), `decomp-further` and node-group
prompt (group `shouldShow=true`, node CUT), carousel `onOpenInPanel` (abstraction `visible=true`), H-click and touch
tap (group HIDE + `selectedGroup=null`; connection HIDE).
What the exiting panel shows is held by render-time latches: `lastSelectedNodePrototypesRef` (~5426),
`lastSingleSelectedInstanceIdRef` (~5446), `lastSelectedGroupRef` (~4636).

### 4.8 Edge pie (E-edge; follows the same "visible / rendered + frozen data" idea, but has no intents)

```
shouldShow = single edge selected ∧ no nodes ∧ ¬carousel ∧ ¬connectionNamePrompt
roseIntoShow = shouldShow ∧ ¬prevShouldShow;  dragJustEnded = prevDragging ∧ ¬dragging
if shouldShow: anchorRef ← live midpoint; if roseIntoShow ∨ dragJustEnded: visible=true, rendered=true

```
Render: `anchor = liveMidpoint || anchorRef`, `buttons = liveButtons.length ? liveButtons : buttonsRef`,

`setEdgePieMenuVisible(false)` to dismiss while the edge stays selected (a "dismissed" state that only re-opens on a
new selection or a drag end). H-click: `visible=false` + clear edge selection.

### 4.9 What the graph-change cleanup resets

**E-cleanup full reset** (only when no guard holds; §2):
selection `new Set()`; `previewingNodeId`; `editingNodeIdOnCanvas`; `editingGroupId`, `tempGroupName` (local);
`plusSign` (local); `nodeNamePrompt` (store); `selectionStartRef` + `selectionStart` (local);
`drawingConnectionFrom` (local); `hoveredEdgeInfo` (local); target; `currentPieMenuData`; `isPieMenuRendered`;
stage 1; stage flag; transitioning; pie colour picker visible + node id (local); carousel visible/node;
`pendingAbstractionNodeId` (**not** `pendingDecomposeNodeId`); focused scale 1.2; focused dims null; focused node
null; anim `hidden`; `pendingSwapOperation` (local); abstraction panel CUT.

**E-closeAll** (always on `activeGraphId`, runs *after* E-cleanup in the same flush): node/connection/abstraction/
group HIDE; `selectedGroup=null`; preview null; selection empty; target null.

Consequences that must be preserved:
- Switching webs **with a node selected and its pie open**: E-cleanup is skipped (guard `size==1 ∧ target`);
  E-closeAll clears target → the pie **plays its shrink at the old node's coordinates in the new web**, then H-pieExit
  closes it. With nothing selected, E-cleanup nulls the data instantly (no shrink).
- E-cleanup also fires on carousel visible↔, exit-guard↓, transitioning↓, and on mount. In practice it resets only
  after T11/T12 teardowns, a watchdog recovery with no single selection, and graph changes without a selection.

## 5. Findings (NEW-n) and ambiguities (A-n)

Confidence is from reading, not reproduction, unless stated. None of these is fixed by the design; the design
reproduces them, and each fix is a separate `fix(canvas): B-…` commit that needs Grant's OK.

- **NEW-1 `carouselClosedByClickAwayRef` is dead.** It is declared (~5171) and only ever assigned `false`
  (~4832, ~10691). The comments at H-cxDone ("Restore the pie menu unless the carousel was closed by a
  click-away") and in H-pieExit row 4 describe behaviour that no longer exists: **a click-away returns the pie to
  the node exactly like Back.** Safe to delete (no behaviour change). *Certain.*
- **NEW-2 Cancelling the abstraction prompt makes the next stage-1 Back a stage swap.** Prompt `onClose` sets
  `isCarouselStageTransition(true)` without a transition (~11285). The flag is only cleared by H-cxClose,
  `submitAbstraction`, H-pieExit 3a, the watchdog (only while transitioning) and E-cleanup. The stage-1
  `carousel-back` action (nodePieButtons ~376–388) does not clear it, so H-pieExit takes row 3a: **Back after a
  cancelled Add Above/Below goes to stage 2 instead of closing the carousel**; the second Back (stage 2) swaps back
  to 1 and clears the flag. Escape/click-away are unaffected (H-cxClose clears the flag). *High; verify by hand
  (F31 stops before cancel).*
- **NEW-3 Carousel Expand races the hurtle.** Expand clears the target and starts a 400 ms hurtle; the carousel exit
  finishes after the pie shrink (≈200 ms for 5–6 bubbles) + 200 ms ≈ 400 ms. If the orb lands first, E-closeAll
  clears the selection, then H-cxDone **restores selection + target to the instance in the old web**. E-cleanup is
  blocked by `carouselExitInProgressRef`, and at +300 ms nothing re-runs it (`justCompletedCarouselExit` was never
  raised on this path, so lowering it is a no-op). The new web can be left with a phantom single selection (the node
  panel's want is true; `selectedNodePrototypes` is empty). Also: the graph change changes H-cxDone's identity (its
  deps include `activeGraphId`), which restarts the carousel's 200 ms exit timer. *Medium; needs a repro.*
- **NEW-4 Closing the carousel from stage 2 leaves `carouselPieMenuStage = 2`.** Escape, click-away and the panel's
  dismiss work in stage 2 (H-cxClose); H-cxDone does not reset the stage (only teardowns, E-cleanup, the prompt and
  submit do). The next carousel open (pie, context menu or control panel) shows the **stage-2 set** first. Same for
  `carouselFocusedNode` and the focused dims ref (these are overwritten on the carousel's first report, so they are
  only momentarily stale). *High for the stage; verify by hand.*
- **NEW-5 Compose acts on whatever is selected when the shrink ends.** H-pieExit row 4 toggles the preview of
  `[...selectedInstanceIds][0]`, not of the node Compose was pressed on. Clicking node B during the ~150 ms shrink
  therefore **decomposes B**. Rows 1–2 are keyed by the pending id, but then set target=A while the selection is B;
  E-sel re-targets to B in the next commit (for row 1 that leaves the carousel open on A with a default pie on B).
  *Medium.*
- **NEW-6 Guard timers are never cancelled.** The 300 ms exit-guard and 100 ms click-guard timers from one exit can
  lower the guards of a following one (reopen + close within 300 ms). *Low.*
- **NEW-7 Losing the selection under the carousel restores a node that may be gone.** T13: E-sel starts the carousel
  exit without a pie shrink, and H-cxDone re-selects the carousel's instance unconditionally. Cmd+X is not in the
  carousel's key guard (useCanvasKeyboard ~634 blocks only Delete/Backspace; cut at ~680–688 removes the node and
  clears the selection), so cut-under-carousel ends with the removed instance selected. *Low–medium; repro needed.*
- **NEW-8 Mouse click-away on a carousel with no pie target needs a second click.** The carousel's `mousedown`
  handler calls `onClose` = H-cxClose (not H-cxReq), which raises the click guard; the following `click` hits
  H-click's click-guard return (~8044) **before** the defensive teardown (~8088). transitioning stays true until the
  watchdog (1.2 s), and E-cleanup is blocked while the carousel is visible. Reachable only when the target was
  cleared under a visible carousel (touch long-press, Wizard). *Low.*
- **A-1** `isVisible`'s `abstractionPrompt.visible || carouselAnimationState === 'exiting'` escape hatches: in every
  path I traced they never make a mounted menu visible (in T9 the data is already null while `exiting`; in T13
  transitioning is false). Kept verbatim in the design; dropping them is a Grant call.
- **A-2** T2's single `isVisible=false` render during a retarget (A→B). The machine sets target and data together,
  which removes it. Probably never painted today; confirm with the reference capture.
- **A-3** `isPieMenuRendered` is redundant with `currentPieMenuData != null` except when the pie's node disappears
  (data null, rendered stays true, E-vision doesn't clear the hover chip). Collapsing it is proposed for phase 2.
- **A-4** T13 (carousel exits without the pie shrinking first) vs. T9 (shrink, then exit). Intended or accidental?
- **A-5** Context-menu Decompose fires the action from the `targetPieMenuButtons` captured when the menu was built,
  100 ms after selecting (so it can interrupt a pop).
- **A-6** Click-away vs. Back: both reopen the pie (NEW-1). The comments say click-away shouldn't. Which is the design?
- **A-7** Compose/Decompose from the control panel skip the shrink/pop that the pie's own buttons play (T5b/T5c).
- **A-8** Teardowns (T11/T12) cut the abstraction panel with no exit animation; the Back path animates it out.

## 6. Proposed design

### 6.1 Principles
1. **One writer.** Every lifecycle field is written only by `dispatchPie(event)` in canvasUIStore. Components,
   builders and hooks emit events; they never call the field setters.
2. **Pure reducer + command runner.** `reducePie(state, event, env) → { patch, commands }` is a pure function in
   `src/components/canvas/pie/pieMachine.js` (the location MAP.md already reserves). The store applies `patch` in
   **one** `set` (so all coupled fields land together; see canvasUIStore's TIMING note), then runs `commands`
   (timers, graphStore writes, camera framing requests).
3. **Derived, not synced.** "Is the pie visible", "which panel wants to show", "reconcile the target from the
   selection" are pure selectors/functions evaluated by the reducer or by the component that renders — never an
   effect that copies one piece of state into another.
4. **Behaviour-exact first.** Phase 1 reproduces every branch in §4 including NEW-2…NEW-8 and the timer
   non-cancellation. Bugs are fixed afterwards, one B-commit each. Removing intermediate renders is allowed (that
   is the point); changing what is painted at an animation boundary is not.

### 6.2 Canonical state (phase 2 shape) and its phase-1 mapping

Phase 1 keeps the existing flat store fields as storage (so ~40 readers don't change) and adds the few locals that
the machine must own. Phase 2 collapses them into the canonical shape once readers go through selectors.

```js
// canonical (phase 2)
pie: {
  target: string|null,                 // selectedNodeIdForPieMenu
  intent: null                         // isTransitioningPieMenu := intent !== null
    | { kind: 'toCarousel', nodeId }   //   + pendingAbstractionNodeId
    | { kind: 'toDecompose', nodeId }  //   + pendingDecomposeNodeId
    | { kind: 'generic' }              //   Compose, Back, close, swap, expand, wizard, stage
    | { kind: 'awaitCarouselExit' },   //   after row 3b, until CAROUSEL_EXITED
  stageFlag: boolean,                  // isCarouselStageTransition — kept SEPARATE from intent in phase 1,
                                       //   because NEW-2 leaves it set with no transition running
  data: { node, buttons, nodeDimensions } | null,   // currentPieMenuData (isPieMenuRendered := data != null, phase 2)
  page: number,                        // pieMenuPage (moved from NodeCanvas)
},
carousel: {
  phase: 'hidden' | 'entering' | 'visible' | 'exiting',   // carouselAnimationState (+ visible := phase !== 'hidden')
  node: object|null,                   // abstractionCarouselNode
  stage: 1 | 2,                        // carouselPieMenuStage
  pendingSwap: object|null,            // pendingSwapOperation (moved)
  exitGuard: boolean,                  // justCompletedCarouselExit
  exitSettling: boolean,               // carouselExitInProgressRef (moved)
  closeRequested: boolean,             // carouselCloseRequestedRef (moved)
  returnFocusId: string|null,          // pendingCarouselReturnFocusRef (moved; consumed by the framing command)
},
clickGuard: boolean,                   // isPieMenuActionInProgress (moved)
marqueeActive: boolean,                // selectionStart != null (new mirror; NodeCanvas writes it where it sets selectionStart)
```

Phase-1 note on `carouselAnimationState` vs `abstractionCarouselVisible`: they are *not* equivalent today for one
render in T6 (`visible=true` with `entering`) and always move together otherwise, so `visible := phase !== 'hidden'`
holds for every write site in §3. Keep both fields in phase 1 anyway and write them together.

### 6.4 Reducer rules (phase 1 = exact)

Every event handler below ends with **`reconcile()`** (§4.1, verbatim, reading the post-patch state and
`marqueeActive`), then **`maybeFullReset(trigger)`** where the trigger is one E-cleanup would have seen
(carousel visibility changed, exit guard lowered, intent cleared, graph changed). Both are idempotent, so calling
them after every event reproduces "re-run when any dep changes" exactly.

```
maybeFullReset(trigger):
  if !trigger: return
  if carousel visible || exitGuard || intent || exitSettling || (selection.size==1 && target): return
  patch the store fields of §4.9 (E-cleanup list); bump `resetNonce` for NodeCanvas locals (see 6.6)
```

| Event | Patch (then reconcile + maybeFullReset) | Commands |
|---|---|---|
| `PIE_TO_CAROUSEL{id}` | if `!carouselVisible ∧ phase=='exiting'` → ignore. `pendingAbstraction=id`, intent=`toCarousel` | arm watchdog |
| `PIE_TO_DECOMPOSE{id}` | same guard; `pendingDecompose=id`, intent=`toDecompose` | arm watchdog |
| `PIE_COMPOSE` | same guard; intent=`generic` | arm watchdog |
| `STAGE_REQUEST` | `stageFlag=true`, intent=`generic` | arm watchdog |
| `CAROUSEL_BACK` | `exitGuard=true`, `clickGuard=true`, intent=`generic` (stageFlag untouched — NEW-2) | `after(100, CLICK_GUARD_ELAPSED)`; arm watchdog |
| `CAROUSEL_CLOSE` | `stageFlag=false`, `exitGuard=true`, `clickGuard=true`, intent=`generic` | same |
| `CAROUSEL_TOUCH_CLOSE` | if `!visible` → no-op; if `closeRequested` → no-op; `closeRequested=true`; if `!target` → as `CAROUSEL_TEARDOWN`; else as `CAROUSEL_CLOSE` | — |
| `CAROUSEL_LEAVE{swap}` | `clickGuard=true`, `pendingSwap=swap??pendingSwap`, target=null, intent=`generic` | `after(100, …)`; arm watchdog |
| `CAROUSEL_TEARDOWN` | visible=false, node=null, phase=`hidden`, stage=1, focused node/dims null | — (maybeFullReset trigger = carousel hidden) |
| `CAROUSEL_OPEN_DIRECT{node}` | if `!visible ∧ phase=='exiting'` → ignore; node, phase=`entering`, visible, target=node.id, selection={node.id} | camera: carousel framing |
| `CAROUSEL_ENTERED` | if phase=='entering' → `visible` | — |
| **`PIE_EXITED`** | §4.2 table rows 1–5 verbatim, with `intent` standing in for transitioning, rows 3b sets intent=`awaitCarouselExit`; row 4 reads `selection` at this moment (NEW-5 preserved) | row 1: camera carousel framing; row 2/4: camera decompose/recompose framing; cancel watchdog when intent clears |
| **`CAROUSEL_EXITED`** | §4.5 verbatim: swap (command), `exitSettling=true`, carousel hidden, intent=null, selection={id}, target=id, `returnFocusId=id`; stage/focused state NOT reset (NEW-4 preserved) | `graph.updateNodeInstance(…)` if swap; `after(300, EXIT_GUARD_ELAPSED)` (never cancelled — NEW-6 preserved); camera: focus `returnFocusId` |
| `EXIT_GUARD_ELAPSED` | `exitGuard=false`, `exitSettling=false` (trigger for maybeFullReset **only if exitGuard actually changed** — this preserves NEW-3's "no re-run") | — |
| `CLICK_GUARD_ELAPSED` | `clickGuard=false` | — |
| `WATCHDOG` | intent=null, stageFlag=false (pendings left as they are, as today) | — |
| `PROMPT_OPEN{…}` | `abstractionPrompt=…` | — |

**Watchdog** = runner timer keyed `'watchdog'`: armed whenever `intent` goes null → non-null, cancelled whenever it
goes back to null (exactly E-watchdog's effect + cleanup). Because `intent` stays non-null through
`awaitCarouselExit`, the 1200 ms budget covers shrink + carousel exit, as today.
