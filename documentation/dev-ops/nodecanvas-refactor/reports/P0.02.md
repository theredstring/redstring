**Dev-only loader**
- **`src/dev/fixtureSandbox.js`** is imported first by `src/main.jsx`. With `?fixture=<name>` it installs, before any app module evaluates:
  - an in-memory `localStorage`, seeded with the onboarding-seen flags
  - a network guard: only same-origin, non-`/api/` requests go through
- **`src/dev/fixtureLoader.js`**:
  - neutralises persistence: SaveCoordinator is forced off, and `universeBackend.initialize` / `WorkspaceService.initialize` are stubbed
  - loads the fixture through the real open-file import path in `universeBackend`
  - exposes `window.__loadFixture(json, opts)` for injected fixtures such as chambers
- **`main.jsx`** mounts the app only after fixture boot succeeds. On failure it shows an error and does **not** fall through to real storage (fail-closed).

## Deviations
- **The stress fixture is committed rather than generated at test time.**
  - The orchestrator first asked for it to be generated. After checking, it reversed that.
  - The repo packs to about 493 MB, and 2.2 MB of repetitive JSON compresses to a small fraction of that.
  - The loader imports the file statically (`?raw`), so it has to exist when the dev server starts.
  - The `--check` script makes any drift visible.

## Handoff
- **Manual use:** `npm run dev`, then open `/?fixture=small` or `/?fixture=stress`. Chambers loads only through the test hook.
- **Changing the fixtures:** after changing the generator, run `npm run fixtures:canvas` and commit both the generator and its output.
- **`main.jsx` is on the app boot path.** Without `?fixture` it behaves exactly as before, but include app boot in the smoke test.
