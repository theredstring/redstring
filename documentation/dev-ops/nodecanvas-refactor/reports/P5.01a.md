# P5.01a report: pie button sets move to builder modules

**Status:** part a done (orchestrator), commit adfa89b. Branch `refactor/p5.01`.

## What changed
- `src/components/canvas/pie/nodePieButtons.js`: `buildNodePieMenuPages`, `buildTargetPieMenuButtons` (with the carousel and decompose sets) and `buildDecomposePanelInfo`.
- `src/components/canvas/pie/edgePieButtons.js`: `buildEdgePieMenuButtons`.
- The bodies are the memos' bodies, moved byte for byte (one indent level less). Each builder takes the render-scope values it closed over as `ctx`. NodeCanvas calls it from the same `useMemo` with the **same dependency list**, so every action closes over exactly what it did before.
- **How the move was checked:**
  - The free variables were found by running ESLint `no-undef` on each body in isolation.
  - Names imported by NodeCanvas became imports of the new module, with paths rewritten; every other name went into `ctx`.
  - Each `ctx` name was checked for a declaration *after* the memo. That would have been a temporal-dead-zone crash when passed eagerly. There is one: `startHurtleAnimation`, declared about 4,000 lines later and only ever called inside actions. It is passed as `(...args) => startHurtleAnimation(...args)`, which still resolves at click time.
  - No `ctx` name is a `let` or is reassigned.

NodeCanvas.jsx: 15,131 → **14,054** lines.
