# P2.06b report: `ModalHosts` (Help, Settings, Merge, Auto Graph)

**Status:** done (orchestrator). **Commits:** `3d10fbb` (test flake, F-77), `93c5764` (P2.06b).

## What changed
- **`src/components/canvas/hosts/ModalHosts.jsx`** (memo, `<Profiler id="ModalHosts">`) is rendered by CanvasShell right after the overlay slot.
  - It subscribes to the four open flags in canvasUIStore.
  - It owns the four window events that open them: `openHelpModal`, `openSettingsModal`, `openMergeModal`, `redstring:open-auto-graph-modal`.
  - Auto Graph's generate reads the active graph and the layout presets from the store when it runs.
- **NodeCanvas** loses the four modals, their four listener effects and their four flag subscriptions. NodeCanvas.jsx: 17,945 → **17,822**.
- **Stacking:** the modals now come after the remaining overlays in DOM order.
  - CanvasModal (Help, Settings, Merge) is z-index 20100+, above everything there, so nothing changes on screen.
  - Auto Graph (20000) now paints over the debug HUD (also 20000) if both are open. That's a debug-only case.

## Test flake fixed (F-77)
- `NodeCanvas.renderBudget.test.jsx`'s marquee test failed about one full `test:ci` run in two, on the pre-P2.06b code too ("expected 1 to be +0", `hold=1`).
- **Cause:** NodeCanvas sets `isInitialLoadComplete` on a real 2 s timer after mount. The test never let it fire, so under the loaded full suite it landed in the hold window.
- **Fix:** `mountAndSettle` waits 2.1 s. After the fix, two full runs both gave `hold=0`.
