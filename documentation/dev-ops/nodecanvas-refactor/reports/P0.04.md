## What changed
- **`npm run perf:canvas`** (`scripts/perf-canvas.mjs`):
  - builds `dist-profile` (Vite mode "profile": React's profiling renderer, real minification, 4 GB heap), serves it with `vite preview`, and runs every scenario 5 times, each on a fresh page
  - prints the median table and writes the raw runs to `test/perf/canvas/results/` (gitignored)
  - flags: `--scenario S1,S6` (`L-S1` for the large fixture), `--runs N`, `--no-build`, `--fixtures medium|large`
- **Scenarios** (`test/perf/canvas/scenarios.js`): S1–S13 exactly as METRICS.md defines them. Targets come from the DOM (the nearest on-screen node, a bare patch of canvas), never from fixed coordinates, because chambers' layout isn't ours.
- **Each run** (`canvas.perf.js`):
  1. Fresh browser context. Requests to anything but localhost are aborted.
  2. Load the fixture: chambers on its largest graph with placeholder thumbnails, or `stress`.
  3. Scenario setup (not measured), then wait until 700 ms pass with no commit.
  4. Start the probe, run the steps, stop once 500 ms pass with no new commit, so glides and follow-up effects count.
- **Fixtures in the profile build** (`ad873f2`): `?fixture=` and `__loadFixture` now also work in mode "profile". A normal production build still drops them (checked: see Verification). `thumbnails: 'placeholder'` seeds the image cache so chambers' Wikipedia thumbnails don't fetch, fail and retry inside a measurement. `window.__imageCache` exposes the thumbnail store for S10.
- **`__renderProbe.peek()`** reads a running session without ending it.
- **The NodeCanvas run/render counter** (`test/perf/canvas/selfRenders.js`, `97c5895`). See the next section.
- **`--explain <ids>`** (`commitLog.js`, `vite.explain.config.mjs`, `b62eda4`):
  - builds `dist-explain`: the profile build, unminified, with each `useState` in NodeCanvas and the canvas hooks tagged with its variable name
  - runs each scenario once and prints every commit: whether NodeCanvas ran, rendered or bailed out, which state and store hooks changed (old → new), and which other components rendered
  - its timings mean nothing; the counts are the point
- **Startup timer:** measurements start at least 2.2 s after NodeCanvas mounts. `isInitialLoadComplete` flips on a 2 s timer (the BackToCivilization delay), and before this fix it landed inside S6's window.

## Commits are not NodeCanvas renders
The probe counts every commit under `<Profiler id="NodeCanvas">`. That includes commits where only a child rendered: the pie menu's own animation, the panel, the carousel. So "NodeCanvas commits" overstates how often the 18k-line component itself renders, and it can't tell a card that stops NodeCanvas rendering from one that doesn't.

`selfRenders.js` counts what NodeCanvas itself did, with no app code:
- **ran:** the NodeCanvas function executed.
- **rendered:** and React kept the result and reconciled its children.
- **ran − rendered** is render bailouts: the whole body ran, found nothing to change, and React discarded the result. They cost the body's time (every hook, every memo dependency check) but no child work.

It installs a stand-in `__REACT_DEVTOOLS_GLOBAL_HOOK__` before React loads and inspects NodeCanvas's fiber after each commit, which works in profiling and production builds. Cross-checked against a counter placed in the function body, on 8 scenarios, one run each: **equal in all 8**.

## Verification
- **Harness:** every scenario passed 5/5 runs in each pass. Commit counts vary by at most ±2 across runs, and most by 0.
- **Counter:** equal to a counter in the NodeCanvas body on 8 scenarios (table above).
- **Separation from the normal suite:** `npx playwright test --list` still collects the 33 canvas flows in 17 files, and no perf files.
- **Build:** a normal production build (`vite build`) contains no fixture code (grep for `__loadFixture`, `fixtureSandbox`, `seedPlaceholderThumbnails` finds 0 files). The profile build does, by design.
- **Integration, after P0.04 + P1.06 + P1.12a:**
  - `lint:undef` PASS
  - `test:ci` PASS: 3,512 tests; 68 failing, all known, 0 new
  - Playwright 34 passed
- **Speed:** one scenario, 5 runs, takes about 35–60 s plus about 10 s to build, so the card's "under a minute" holds only with `--no-build`.
- **Lint:** `canvas.perf.js` reads `process.env`, which ESLint flags in `test/perf`. That was already so in the e2e helpers; `lint:undef` only gates `src/`.
