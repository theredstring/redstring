## What changed (`src/NodeCanvas.jsx`)
- **Edges pass:** deleted the `edgePairGroupsDebug` build (a sort and join per visible edge on every render) and the `debugLogSync('NodeCanvas.jsx:edgeRender', …)` POST it fed. Also deleted the now-unused `debugLogSync` import. `debugLogger.js` is still imported by the four modules listed under NEW-2.
- **ArrowheadAudit: deleted, not moved** (the loop in the edges pass plus `arrowheadAuditSeenRef`). Reasons:
  - It was a one-off investigation aid added with an edge-creation fix in 296cb8b (2026-04-21), and it has only ever `console.warn`ed.
  - Checked against the Claude's Chambers fixture: 1,090 edges carry `directionality`, 1,056 have arrows, and **0** have an `arrowsToward` id that isn't one of the edge's endpoints. (I printed counts only.) So on real data it has nothing to report.
  - Keeping it as a flagged effect would leave about 30 lines of diagnostics in the file this refactor is shrinking. The natural home for an opt-in version is a `__diag.arrowheads()` command in `src/utils/canvasDiagnostics.js`, which is outside this lane's files. The code can be recovered from 296cb8b if Grant wants that.
- **`DIAGNOSE_ZOOM_FLICKER = true`** ("TEMPORARY", pointing at a plan file outside the repo) and all three blocks it gated are deleted:
  - the `[flicker:svg-conditions]` effect, which warned on every universe-gate flip
  - the `[flicker:nodes-memo]` warning inside the `nodes` memo
  - the `[flicker:culling]` reasons block inside `runCulling`
- No behaviour change: every removed statement was logging, a fetch, or a local that fed them.
